## 1. 2026-10-14 · 位置式 PID 的三处补丁

### 1.1 补丁 A：首拍微分尖峰

**现象**（可直接复现）：

```python
from src.pid.position_pid import PositionPID

pid = PositionPID(kp=1.0, ki=0.0, kd=0.5, dt=0.01)
print(pid.update(setpoint=1.0, measurement=0.0))
# 期望 1.0（只有比例作用），实际 51.0
```

**根因**：`reset()` 把 `self._prev_error` 初始化成 `0.0`。首拍时并不存在「上一拍的误差」，但代码按「上一拍误差 = 0」去算微分：

```
D = kd · (e[0] − e[−1]) / dt = 0.5 · (1 − 0) / 0.01 = 50
u = 1 + 50 = 51
```

这不是阶跃本身导致的微分作用（那是 B），而是**凭空多出来的 50**——因为 `e[−1]` 是个假值。

**补丁**：首拍没有记忆时，微分按 0 处理（`bumpless start`）。

```python
def reset(self):
    self._integral = 0.0
    self._prev_error = None      # ← 改成 None：首拍代表"没有上一拍"
    self._prev_measure = None

def update(self, setpoint, measurement):
    error = setpoint - measurement
    if self._prev_measure is None:      # 首拍：补齐记忆，不产生微分
        self._prev_measure = measurement
        self._prev_error = error
    ...
```

> 另一种等价做法是构造时传入初始测量值 `pid.reset(measurement=25.0)`，让控制器"从当前状态接管"——这就是工业上说的**无扰动切换**。本题用 `None` 标记首拍更省事。

### 1.2 补丁 B：微分先行（derivative on measurement）

**现象**：

```python
pid = PositionPID(kp=1.0, ki=0.0, kd=0.5, dt=0.01)
pid.update(0.0, 0.0)          # 已经是稳态
print(pid.update(1.0, 0.0))   # 设定值跳变，测量值根本没动
# 期望 1.0，实际 51.0
```

**根因**：D 项算的是**误差**的变化率，而误差 = 设定值 − 测量值。设定值一跳，即使被控对象纹丝不动，D 项也会瞬间爆一个尖峰。这就是 **微分冲击（derivative kick）**。

> 注意：这正是你在 `incremental_pid.py` 注释里已经写对的那件事——「增量式并不能消除微分冲击，真正的解法是微分先行」。位置式这边当时没落地。

**补丁**：让 D 项只对**测量值**求导。

```python
# 改前
derivative = (error - self._prev_error) / self.dt

# 改后（注意负号：测量值增大 = 误差减小 = 负的微分作用）
derivative = -self.kd * (measurement - self._prev_measure) / self.dt
```

代价：设定值变化时不再有"提前刹车"，完全靠 P 推。工业上绝大多数 PID 都这么干，因为**微分冲击造成的执行器冲击比少一点刹车危险得多**。

### 1.3 补丁 C：条件积分 → back-calculation

**现象**（比较隐蔽，不会一眼看出）：

条件积分只在「**已经**饱和」时冻结积分。饱和发生的那一拍，积分已经写进去了；更麻烦的是，一开始饱和就把积分冻在一个"过期"的值上，等退出饱和时这个值还在，于是超调。

**补丁**：先算出未限幅输出 `u_unsat`，限幅得到 `u`，再把「超出多少」按 `1/Tt` 反算回积分器。

```python
integral_next = self._integral + self.ki * error * self.dt
u_unsat = self.kp * error + integral_next + derivative
u = self._saturate(u_unsat)
self._integral = integral_next + self.track_gain * (u - u_unsat) * self.dt
```

`track_gain = 1/Tt`，缺省取 `Tt = Ti = kp/ki`：

```python
@property
def track_gain(self):
    if self.tt is not None:
        return 1.0 / self.tt
    if self.kp == 0 or self.ki <= 0:
        return 0.0                 # 没有 I 项就不需要跟踪
    return self.ki / self.kp       # 1/Ti
```

**怎么验证它确实有用**（不是断言，而是一段对比脚本）：

```python
def run(mode, steps_sat=300):
    """同一组参数，饱和 300 拍后看积分残余"""
    pid = PositionPID(kp=1.0, ki=2.0, kd=0.0, dt=0.01, output_limits=(0.0, 10.0))
    for _ in range(100):
        pid.update(1.0, 0.0)            # 未饱和，积分充到 ~2.0
    for _ in range(steps_sat):
        pid.update(20.0, 0.0)           # 大幅饱和
    return pid._integral
```

- 条件积分：积分**冻结**在 2.0，一直不降；
- back-calculation：积分被持续往合理值拉（本组参数下收敛到约 10，取决于 `Tt`）。

两者差多少，取决于 `Tt` 取得多激进。`Tt` 越小，回退越快、但容易把积分拉过头。

> **所以补丁 C 的测试是「护栏」性质**：它不会在改前变红，只在你以后手贱把抗饱和删掉时变红。A、B、E 那三条才是真正的红→绿。

### 1.4 合并后的完整类（可直接替换）

```python
class PositionPID:
    """位置式 PID（补丁 A/B/C 已合并）。"""

    def __init__(self, kp=1.0, ki=0.0, kd=0.0, dt=0.01,
                 output_limits=(None, None), tt=None):
        self.kp = float(kp)
        self.ki = float(ki)
        self.kd = float(kd)
        self.dt = float(dt)
        self.lo, self.hi = output_limits
        self.tt = tt                    # 反向计算时间常数；None → Ti = kp/ki
        self.reset()

    def reset(self):
        self._integral = 0.0
        self._prev_error = None         # 首拍没有"上一拍"
        self._prev_measure = None
        self._last_output = 0.0

    @property
    def track_gain(self):
        """back-calculation 的 1/Tt"""
        if self.tt is not None:
            return 1.0 / self.tt
        if self.kp == 0.0 or self.ki <= 0.0:
            return 0.0
        return self.ki / self.kp

    def _saturate(self, u):
        if self.hi is not None and u > self.hi:
            return self.hi
        if self.lo is not None and u < self.lo:
            return self.lo
        return u

    def update(self, setpoint, measurement):
        error = setpoint - measurement

        # 补丁 A：首拍补齐记忆，不产生假微分
        if self._prev_measure is None:
            self._prev_measure = measurement
            self._prev_error = error

        # 补丁 B：微分先行，只对测量值求导
        derivative = -self.kd * (measurement - self._prev_measure) / self.dt

        # 补丁 C：back-calculation
        integral_next = self._integral + self.ki * error * self.dt
        u_unsat = self.kp * error + integral_next + derivative
        u = self._saturate(u_unsat)
        self._integral = integral_next + self.track_gain * (u - u_unsat) * self.dt

        self._prev_measure = measurement
        self._prev_error = error        # 保留仅为兼容，已不参与计算
        self._last_output = u
        return u
```

**行为变化**（跑 `examples/day1_position_pid.py` 会看到的差异）：

- 第一拍的 `u` 从 51 变成 1（补丁 A）；
- 设定值阶跃处不再有 D 尖峰，曲线更"钝"（补丁 B）；
- 饱和段之后的超调变小（补丁 C）。

**这三条都改变了曲线形状**，所以 `docs/images/day1_position_pid.png` 需要重拍，README 里如果有具体数字（超调/上升时间）要跟着改。

## 2. 2026-10-15 · 增量式 PID：dt 抖动（补丁 D）

### 2.1 现象

你在 `incremental_pid.py` 里写了「增益配平后增量式与位置式代数等价」，推导是对的。但这个等价性有一个从来不写在公式里的前提：**dt 是常数**。

同一个控制器、同一段输入，只把 `dt` 从 0.010 改成 0.011：

```python
p_nom = IncrementalPID(kp=2.0, ki=10.0, kd=0.0, dt=0.010)
p_jit = IncrementalPID(kp=2.0, ki=10.0, kd=0.0, dt=0.011)
for _ in range(200):
    p_nom.update(1.0, 0.0)
    p_jit.update(1.0, 0.0)

print(p_nom._last_output, p_jit._last_output)   # 20.0 vs 22.0 —— 差 10%
```

### 2.2 根因

```text
du = kp*(e − e_prev) + ki*e*dt + kd*(e − 2e_prev + e_prev2)/dt
```

`dt` 在积分项里是**乘**（线性），在微分项里是**除**（反比）。`dt` 偏大 10% 时：

- 积分项偏大 10%；
- 微分项偏小约 9.1%；
- **两者朝相反方向错，不会互相抵消。**

而位置式那边，`dt` 只出现在微分的除里，误差方向单一。这就是"等价"这件事在真实硬件上会松动的地方。

### 2.3 补丁 D：把前提钉成断言

这条不是 bug，是**前提条件**。补丁分三处：

**① 在类注释里补一句硬前提**

```python
# 与位置式代数等价的前提：dt 恒定。
# dt 抖 10% 时，积分项错 +10%、微分项错 −9.1%，两者不再抵消。
# 嵌入式里必须由定时器中断保证等间隔，不能 HALL_Delay(10)。
```

**② 构造时做一次自检**（防手滑传入 0 或负数）

```python
def __init__(self, kp=1.0, ki=0.0, kd=0.0, dt=0.01, output_limits=(None, None)):
    if dt <= 0:
        raise ValueError("dt 必须为正的采样周期（秒）")
```

**③ 配一条文档型测试**（永远绿，但把数字钉住）

见 §4 的 `test_D_dt_jitter_breaks_equivalence`。

> 为什么不改成「每次传入实测 dt」？那属于接口重设计，会牵动 `examples/` 里所有调用点。等你上 P1 硬件、真的要读定时器计数时再做，那时你才有真实 dt 可用。

## 3. 2026-10-17 · 一阶低通：from_cutoff 的边界（补丁 E）

### 3.1 现象

```python
from src.filter.lowpass import FirstOrderLowPass

lp = FirstOrderLowPass.from_cutoff(cutoff_hz=100.0, dt=0.01)   # fs = 100 Hz
print(lp.alpha)   # 0.0
lp.update(5.0)    # 5.0
lp.update(1.0)    # 还是 5.0 —— 滤波器彻底冻结
```

### 3.2 根因

`from_cutoff` 解的是 `cos(2π·fc·dt) = (2 − 2α − α²) / (2(1−α))`。

`fc = fs` 时 `2π·fc·dt = 2π`，`cos = 1`，于是 `k = 1−cos = 0`，解得 `α = −k + √(k(k+2)) = 0`。

递推式退化成 `y[k] = y[k−1]`——输出永远是初值。这不是"滤波太狠"，是**离散解在奈奎斯特频率以上发生了折叠**：`fc = fs` 和 `fc = 0` 在离散域里是同一个点。

### 3.3 补丁 E：卡死边界并报错

```python
@classmethod
def from_cutoff(cls, cutoff_hz, dt):
    """由 -3dB 截止频率和采样周期反推 alpha（离散域精确解）。"""
    if dt <= 0:
        raise ValueError("dt 必须为正的采样周期（秒）")
    fs = 1.0 / dt
    if not (0.0 < cutoff_hz < fs / 2.0):
        raise ValueError(
            f"cutoff_hz={cutoff_hz} Hz 必须落在 (0, fs/2) = (0, {fs/2:.1f}) Hz 内；"
            f"超过奈奎斯特频率时离散解会折叠，alpha 会跳到 0，滤波器直接冻结"
        )
    c = math.cos(2.0 * math.pi * cutoff_hz * dt)
    k = 1.0 - c
    alpha = -k + math.sqrt(k * (k + 2.0))
    return cls(alpha=min(max(alpha, 1e-6), 1.0))     # 双保险
```

**边界行为对照**（`fs = 100 Hz`）：

| `cutoff_hz` | α | 表现 |
|---|---|---|
| 0.5 | 0.031 | 很平滑，延迟大 |
| 5 | 0.28 | 常用区间 |
| 44 | 0.94 | 接近直通（MPU6050 的 DLPF 常配这个） |
| **50（fs/2）** | 0.83 | 奈奎斯特边界，再高就折叠 |
| **100（fs）** | **0** | **冻结** ← 补丁拦的就是这里 |

> 顺带记住一句话：**α 和采样率是绑定的**。同一个 `α = 0.98`，100 Hz 下时间常数是 0.49 s，200 Hz 下只有 0.24 s。若要"跨采样率保持同样的滤波强度"，就必须用 `from_cutoff`，不能直接给 α。

## 4. 回归测试：把这三处 bug 钉成红灯

新建 `tests/test_patches.py`：

```python
"""Day 1–3 补丁的回归测试。

跑法（在 control-algorithms 根目录）：
    python -m pytest tests/test_patches.py -v

预期：打完补丁后 6 条全绿；未打补丁时 A / B / E 三条为红。
"""
import pytest

from src.pid.position_pid import PositionPID
from src.pid.incremental_pid import IncrementalPID
from src.filter.lowpass import FirstOrderLowPass


def test_A_first_step_no_derivative_spike():
    """补丁 A：首拍没有"上一拍"，微分必须按 0 处理。
    改前 u = 1 + 0.5*(1-0)/0.01 = 51.0；改后 = 1.0
    """
    pid = PositionPID(kp=1.0, ki=0.0, kd=0.5, dt=0.01)
    assert pid.update(1.0, 0.0) == pytest.approx(1.0)


def test_B_setpoint_step_no_derivative_kick():
    """补丁 B：设定值阶跃、测量值没动，就不该有微分冲击。"""
    pid = PositionPID(kp=1.0, ki=0.0, kd=0.5, dt=0.01)
    pid.update(0.0, 0.0)                          # 先到稳态
    assert pid.update(1.0, 0.0) == pytest.approx(1.0)


def test_B_measurement_noise_still_damped():
    """补丁 B 不能把 D 项彻底废掉：测量值真的变了，D 必须出力。"""
    pid = PositionPID(kp=1.0, ki=0.0, kd=0.5, dt=0.01)
    pid.update(0.0, 0.0)
    u = pid.update(0.0, 1.0)      # 测量值跳变 1.0 → D = -0.5*1/0.01 = -50
    assert u == pytest.approx(-1.0 - 50.0, rel=1e-6)


def test_C_integral_bounded_under_long_saturation():
    """补丁 C 的护栏：长时间饱和，积分不得无限增长。"""
    pid = PositionPID(kp=10.0, ki=5.0, kd=0.0, dt=0.01, output_limits=(0.0, 1.0))
    for _ in range(500):
        pid.update(10.0, 0.0)
    assert pid._integral <= 1.0


def test_D_dt_jitter_breaks_equivalence():
    """补丁 D（文档型）：等价性依赖恒定 dt。dt 抖 10%，输出差 10%。"""
    p_nom = IncrementalPID(kp=2.0, ki=10.0, kd=0.0, dt=0.010)
    p_jit = IncrementalPID(kp=2.0, ki=10.0, kd=0.0, dt=0.011)
    for _ in range(200):
        p_nom.update(1.0, 0.0)
        p_jit.update(1.0, 0.0)
    assert abs(p_nom._last_output - p_jit._last_output) > 1.0   # 20.0 vs 22.0


def test_E_cutoff_beyond_nyquist_raises():
    """补丁 E：fc = fs 时离散解折叠成 α=0，必须报错而不是静默冻结。"""
    with pytest.raises(ValueError):
        FirstOrderLowPass.from_cutoff(cutoff_hz=100.0, dt=0.01)   # fs = 100 Hz


def test_E_cutoff_normal_usage_unaffected():
    """补丁 E 不能误伤正常用法。"""
    lp = FirstOrderLowPass.from_cutoff(cutoff_hz=5.0, dt=0.001)   # fs = 1000 Hz
    assert 0.0 < lp.alpha < 1.0
```

**测试 4 的数值**（`test_B_measurement_noise_still_damped`）：`u = kp*e + kd*D`，`e = 0 − 1 = −1`，`D = −0.5 * (1 − 0)/0.01 = −50`，所以 `u = −1 − 50 = −51`。这条很关键——它防止补丁 B 被写成"把 D 直接关掉"。

## 6. 一句话总结

**A 和 B 是「代码写对了公式、但没写对边界」，E 是「数学解在边界上退化而没拦」——这三类 bug 的共同点是：它们不会让你的仿真报错，只会让你的曲线悄悄变难看。** 这就是为什么 §4 那几个断言值得写：它们把"看起来还行"变成"要么绿要么红"。
