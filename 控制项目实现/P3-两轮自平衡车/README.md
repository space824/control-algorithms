## 5. 建模：从牛顿方程到状态空间（Day 8 + Day 15 的实战）

### 5.1 简化模型：小车-倒立摆

把两轮车等效成「质量为 M 的小车 + 质量为 m、质心距轴 l 的摆杆」：

```
M : 车轮 + 底座 + 电机的等效质量（参与平动的部分）
m : 轴以上车身的质量
l : 轴心到车身质心的距离
x : 车的位移        θ : 车身倾角（竖直向上为 0，前倾为正）
u : 等效驱动力 F = 2·τ_motor / r_wheel
```

忽略摩擦与轮子转动惯量，小角度线性化后：

```
(M+m)ẍ + m l θ̈ = F
ẍ + l θ̈ − gθ = 0
```

消去后得到：

```
ẍ = F/M − (m g / M) θ
θ̈ = ((M+m) g / (M l)) θ − F / (M l)
```

取状态 `x = [x, ẋ, θ, θ̇]ᵀ`，写成 `ẋ = A x + B u`：

```
      ⎡ 0   1        0        0 ⎤          ⎡    0    ⎤
A  =  ⎢ 0   0    −m·g/M       0 ⎥      B = ⎢  1/M    ⎥
      ⎢ 0   0        0        1 ⎥          ⎢    0    ⎥
      ⎣ 0   0  (M+m)g/(M·l)    0 ⎦          ⎣ −1/(M·l)⎦
```

**符号自检**：`A[1][2] = −m g/M < 0` 说明「前倾 → 车往负方向加速」，要抵消前倾就得给正 F（轮子往车身后方追）。这与骑车直觉一致，说明模型符号没错。

### 5.2 用 sympy 自己推（推荐做一遍）

```python
import sympy as sp
M, m, l, g, F = sp.symbols('M m l g F', positive=True)
xdd, thdd, th = sp.symbols('xdd thdd th')

# 线性化方程组
eq = [sp.Eq((M+m)*xdd + m*l*thdd, F),
      sp.Eq(xdd + l*thdd - g*th, 0)]
sol = sp.solve(eq, [xdd, thdd], dict=True)[0]
print(sp.simplify(sol[xdd]))     # F/M - m*g*th/M
print(sp.simplify(sol[thdd]))    # ((M+m)*g*th - F)/(M*l)
```

在 `../../examples/` 里加一个 `day8_state_space.py`，把 A/B 建起来画自由响应（`scipy.signal.lsim`），**正好完成你计划里 Day 8 的任务**，而且用的是自己的车参数。

### 5.3 参考参数与增益计算

假设你的车：`M = 0.7 kg, m = 0.8 kg, l = 0.10 m, g = 9.81`：

```python
import numpy as np
from scipy.linalg import solve_continuous_are
from scipy.signal import cont2discrete

M, m, l, g = 0.7, 0.8, 0.10, 9.81
A = np.array([[0, 1, 0, 0],
              [0, 0, -m*g/M, 0],
              [0, 0, 0, 1],
              [0, 0, (M+m)*g/(M*l), 0]])
B = np.array([[0], [1/M], [0], [-1/(M*l)]])

Q = np.diag([1.0, 1.0, 10.0, 1.0])   # 位置, 速度, 角度, 角速度
R = np.array([[1.0]])

P = solve_continuous_are(A, B, Q, R)
K = np.linalg.solve(R, B.T @ P)
print("K =", K.round(2))             # u = -K @ [x, xdot, theta, thetadot]
```

**`Q` 怎么选**：

| 想要的行为 | 调整 |
|---|---|
| 更在意「别倒」 | 增大 `Q[2][2]`（角度项） |
| 更在意「别乱跑」 | 增大 `Q[0][0]`（位置项） |
| 控制更温柔 / 省电 | 增大 `R` |
| 动作太软、恢复慢 | 减小 `R` |

**规律**：`K` 里角度分量（第 3 个元素）通常比其他分量大一个数量级——因为直立是首要目标，位置可以慢慢回。

## 6. 阶段一：串级 PID 直立（先让它站起来！）

**别一上来就写 LQR。** 原因：LQR 的输出是**物理力 F（牛顿）**，你需要把 F 标定成 PWM；而串级 PID 直接输出 PWM，没有标定问题。**先用串级 PID 拿到一个能站住的基线，再用 LQR 去挑战它**，这样对比才有说服力。

### 6.1 控制结构

```
        ┌──────────────── 5 ms 中断 ─────────────────┐
        │                                            │
  θ_ref(+)                                                  PWM_L
   ▲      ▼                                            ┌──► 左轮
   │  [角度环 PD] ──► 限幅 ──┬─────────────────────────┤
   │   Kp_θ, Kd_θ            │                         └──► 右轮
   │                         │ + 转向差速 ◄─ [转向环 P] ◄── 陀螺 Z 轴
   │                         │
   │  [速度环 PI] ◄── v_meas ◄── (编码器左+右)/2
   │   Kp_v, Ki_v   （v_ref = 0 或摇杆指令）
   └──── 输出的是「角度偏置 θ_ref」
```

**内环（角度 PD）**：响应最快的环，5 ms 周期。
**外环（速度 PI）**：约 50–100 ms 尺度，输出是「让车稍微前倾一点」的角度设定值——这就是平衡车能保持位置的原因（前倾就会往前走，用位置误差反推该倾多少）。

### 6.2 实现要点

```c
/* 5 ms 中断 */
float theta   = attitude_get();             /* 来自 P2, 单位度 */
float gyro_x  = attitude_get_rate();        /* 度/秒 */

/* 外环: 速度环, 输出角度偏置 */
float v_meas = (enc_left_speed + enc_right_speed) * 0.5f;
float theta_ref = pid_v_calc(&pid_v, v_target, v_meas);   /* 限幅 ±8 度 */

/* 内环: 角度环 PD */
float e_theta = theta_ref - theta;
float u_balance = pid_theta.kp * e_theta
                - pid_theta.kd * gyro_x;      /* 用角速度做 D, 比差分更干净 */

/* 转向: 差速 */
float u_turn = pid_turn.kp * (yaw_target - gyro_z);

motor_left_set (u_balance + u_turn);
motor_right_set(u_balance - u_turn);
```

三个易错点：

1. **角度环的 D 项要用陀螺角速度，不要对角度差分**——差分把噪声放大了 10 倍。
2. **速度环输出限幅**（±8°）：不限幅的话，速度误差大时车会「趴下去追」，直接倒地。
3. **转向用陀螺 Z 轴闭环**，不要用编码器差速（编码器差速在打滑时失效）。

### 6.3 调试顺序（**严格按顺序，别跳**）

| 步 | 做什么 | 判据 |
|---|---|---|
| 1 | 车架空（轮子悬空），验证两轮正反转方向与 PWM 符号一致 | 给正 u 两轮都往前转 |
| 2 | 验证倾角符号：车**前倾**时 `theta` 应为**正** | 用串口看数值，手慢慢压车 |
| 3 | **符号联调**：前倾时 `u_balance > 0`（轮子往前追） | 这一步错=必翻车，务必测 |
| 4 | 手扶车，只开角度 P（`Kp=8`, `Kd=0`），感受是否"有抵抗力" | 它应该试图往反方向纠正 |
| 5 | 加 D（`Kd=1.5` 起），消除抖动 | 抖动消失、有阻尼感 |
| 6 | 松手 2–3 秒站立 | 站住即可，漂走不管 |
| 7 | 加速度环 PI（`Kp=15, Ki=2`） | 不再漂走、能定住位置 |
| 8 | 加转向环 | 能按指令原地转 |
| 9 | 轻推测试 | 推一下能自己回来 |

> 起始参数（度 / 归一化输出，`Kp=8~15, Kd=1~3`）只是量级参考。**第 4–5 步一定要扶着做**，第一版必然抖。

## 7. 阶段二：换成 LQR

### 7.1 关键难点：物理量 → PWM 的标定

LQR 算出来的是 `u = -Kx`，单位是**牛顿**。但你的执行器是 PWM 占空比。中间有个未知系数：

```
PWM ≈ k_pwm · F   →   k_pwm 需要标定
```

**标定方法**（选一个）：

| 方法 | 做法 | 精度 |
|---|---|---|
| 静态力标定 | 车平放，给不同 PWM 让轮子顶住电子秤/弹簧秤，测推力 | 好，需秤 |
| 动态响应标定 | 车架空，给阶跃 PWM，测角加速度 `θ̈`，与模型 `θ̈ = ... F` 反推 | 中，需高精度陀螺 |
| **工程近似（推荐）** | 用串级 PID 的等效增益反推：`k_pwm ≈ Kp_θ / K_angle` | 够用 |

**残酷的现实**：简化模型忽略了轮子转动惯量、电机电枢电感、减速箱摩擦，**算出来的 K 直接上必不完美**。所以：

> **落地策略**：先按 `k_pwm` 标定的值跑，然后把 LQR 输出的整体增益乘一个系数 `γ`（0.5–1.5）现场扫。γ 太小 → 软、站不住；γ 太大 → 高频抖。**扫这个单参数比重新推模型快得多。**

### 7.2 代码骨架

```c
/* 离线算好的 K (4 个元素), 5 ms 中断里只做一次乘加 */
static const float K[4] = { -0.30f, -0.28f, 12.5f, 1.6f };   /* 示例, 必须用你自己的 */
static float gamma = 1.0f;        /* 现场微调系数, 串口可改 */

void balance_lqr(void)
{
    float x[4];
    x[0] = pos_meas;              /* 里程计位置, m; 原点每次上电清零 */
    x[1] = vel_meas;              /* 速度, m/s */
    x[2] = theta * DEG2RAD;       /* 倾角, rad */
    x[3] = gyro_x * DEG2RAD;      /* 角速度, rad/s */

    float u = 0.0f;
    for (int i = 0; i < 4; i++) u -= K[i] * x[i];
    u *= gamma * k_pwm;           /* 换成 PWM 量纲 */

    /* 速度积分补偿: 消除模型误差导致的缓慢漂移 */
    vel_int += KI_V * x[1] * DT;
    if (vel_int >  0.15f) vel_int =  0.15f;
    if (vel_int < -0.15f) vel_int = -0.15f;
    u -= vel_int;

    motor_left_set (u + u_turn);
    motor_right_set(u - u_turn);
}
```

**为什么必须有这个积分项**：LQR 是「模型最优」的，模型不准时位置会以恒定速度漂走（`x` 不可控）。加一个对 `x[1]` 的小积分，是 LQR 落地最常见的工程补丁（也叫 LQI, Linear Quadratic Integral）。

### 7.3 离散化（更严谨的做法）

5 ms 采样在嵌入式上直接当连续系统用通常没问题，但想严谨就离散化后算 `dlqr`：

```python
from scipy.signal import cont2discrete
import numpy as np
from scipy.linalg import solve_discrete_are

dt = 0.005
Ad, Bd, _, _, _ = cont2discrete((A, B, np.eye(4), np.zeros((4,1))), dt,
                                method='zoh')
P = solve_discrete_are(Ad, Bd, Q, R)
Kd = np.linalg.solve(R + Bd.T @ P @ Bd, Bd.T @ P @ Ad)
```

> 判据：看 `A` 的特征值，最快模态的时间常数约 `1/sqrt(210) ≈ 70 ms`，而采样周期 5 ms，**采样率是控制带宽的 10 倍以上，直接用连续 K 完全够**。

## 10. 常见坑

1. **符号错 → 满速倒地**：这是最危险的错。**§6.3 第 2–3 步必须做**，且在架空/扶墙状态下做。
2. **倾角符号在车里被翻转**（IMU 装反了方向）：改 `attitude.c` 里的符号，不要改控制器的符号——控制器要能同时适配车和倒立摆。
3. **电机方向不对称**：两轮一个正一个反，转向会失控。用「向前推车应该两轮都向前」的测试排掉。
4. **5 ms 中断超时**：`atan2f` + 卡尔曼 + 串口都塞进去，周期超 5 ms → 失控。用 GPIO 翻转测实际耗时，**中断里只允许纯浮点四则运算**。
5. **电池电压下降导致增益漂移**：满电 12.6 V、快没电 9.5 V，同样 PWM 扭矩差 30%。要么加电压补偿（`u /= v_bat/12.0`），要么每次充满电测试。
6. **编码器线被轮子绞断**：扎带固定走线，留活动余量。
7. **重心太高 + 车架软**：整个车变成弹簧振子，任何增益都振。**车架必须是刚体**。
8. **LQR 直接上、不做 γ 扫**：模型误差会让它抖。先扫 γ。
9. **位置 `x` 用编码器累计但没换算成米**：`x = counts / (1320) * π * D`。单位混用会让 K 全错。
10. **测试场地太小**：车会冲出去撞墙。至少 2×2 m 空地，铺防滑垫。

## 11. 安全清单（做之前读一遍）

- [ ] **主电源开关**装在伸手可及处，倒地第一时间断电
- [ ] 电池有**保护板**，正极串 5 A 保险丝
- [ ] 电机线、电池线用扎带固定，避免倒地时扯断短路
- [ ] 轮子转动部件加小挡板，防止夹手
- [ ] 不要在桌边测试（会掉下去）
- [ ] 调试时**先架空，再扶墙，最后放手**——每次改参数都回到第 1 步

## 12. 软件侧

- **模型验证**：把实测的 PWM→倾角响应和 `scipy.signal.lsim` 的仿真响应叠图。如果形状完全不对，说明 `M/m/l` 估错了；如果只是慢一点，说明忽略了摩擦/惯量。
- **在线调参**：串口协议加一条 `SET kp_theta 12.5` 命令，避免每改一个参数烧一次固件（细节见 [上位机与工具链.md](../公共资料/上位机与工具链.md)）。
- **数据记录**：一次测试录 `t, theta, theta_ref, pos, vel, u, gyro_z` 七列，CSV 用文件名带参数（`p3_K_0.3_12.5_g1.0.csv`）。

---

## 13. 延伸

- **位置跟踪**：给定 `x_ref` 做梯形速度规划，从平衡车变成「能走指定距离的车」。
- **路径跟踪**：加转向后接 Pure Pursuit / Stanley，就是你 `../../smart-car/` 里想做的事。
- **MPC**：把 LQR 换成 20 步 MPC，能显式处理「PWM 饱和」和「倾角不能超过 15°」的约束。但 F103 算力紧张，需先用显式 MPC 或降采样，**建议先在电脑上离线跑通再移植**（见 [P5](../P5-恒温箱MPC/README.md) 的 QP 部分）。
- **鲁棒性**：给 `M`、`m`、`l` 各加 ±20% 扰动，看 LQR 的稳定裕度——这是很好的报告素材。
