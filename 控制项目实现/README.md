# 控制项目实现 · 从仿真到硬件

> 依据 `../控制算法学习计划.txt` 的四周路线，把「纯 Python 仿真」升级成「能上电、能跑、有实测数据」的硬件小项目。
> 起点：Day 3（一阶低通滤波已跑通）｜主控：STM32F103C8T6（`../stm32-hal` 已验证 HAL）｜预算：¥0 ~ ¥600 分档

---

## 0. 一句话方案

前四周的计划是**纯软件建库**，最大的风险是「算法会写、板子上跑不起来」。

这套文档用 5 个**彼此独立**的小项目，把每个算法都焊到真实的执行器和传感器上。每个项目必须产出三样东西：

1. **能跑的固件**（不是能编译，是能闭环）
2. **一段实测 CSV 数据**
3. **一张「仿真 vs 实测」对比图**

这三样才是简历、毕设、面试里真正值钱的东西——「我实现过 PID」和「我的电机 100 ms 跟上 300 RPM、超调 8%、有阶跃曲线为证」是两个量级。

## 1. 目录结构

**一个项目一个文件夹，每个文件夹都是自包含的**，可以单独打开、单独推进，不看别的目录也能做。

```
控制项目实现/
├── README.md                      ← 本文件：索引、排期、预算、打卡
│
├── P1-直流电机速度闭环/
│   └── README.md                  编码器测速 + 定时器 PID + 一阶模型辨识
├── P2-姿态解算与互补滤波/
│   └── README.md                  MPU6050 + 互补滤波 → KF → EKF
├── P3-两轮自平衡车/
│   └── README.md                  串级 PID → LQR（旗舰项目）
├── P4-单级倒立摆/
│   └── README.md                  能量起摆 + 欠驱动 LQR / MPC（选修）
├── P5-恒温箱MPC/
│   └── README.md                  FOPDT 辨识 + 滚动优化 + 约束
│
└── 公共资料/                      ← 只有跨项目通用的东西放这里
    ├── 接线与安全规范.md          供电共地、驱动选型、编码器/IMU 接线、保护、安全红线
    └── 上位机与工具链.md          串口协议、Python 上位机、指标计算、参数巡参
```

**每个项目 README 都是同一套骨架**，按顺序读就行：

| 小节 | 内容 |
|---|---|
| §1 项目目标 | 做到哪三件事就算完成 |
| §2 为什么选它 | 它在整条学习路径上的位置 |
| §3 硬件清单 | BOM 表：型号、数量、参考价、选购要点 |
| §4 接线 | 引脚分配表 + 供电接法 |
| §5 控制结构 | 框图 + 任务频率划分 |
| §6–7 分阶段实现 | Step 0…N，每步带验收判据；含关键代码骨架 |
| §8–9 整定与验收 | 起始参数、调参方向、可量化的验收指标 |
| §10 常见坑 | 编号清单，按踩坑概率排序 |
| §11–12 软件侧 / 交付物 | 上位机怎么配合、最后要交出什么 |

> 通用规则（共地、电容、保护、安全）**不再在每个项目里重复**，统一在 [`公共资料/接线与安全规范.md`](公共资料/接线与安全规范.md)，每个项目文档开头都有链接。

**复用关系**（这套项目的价值在于串起来，但**从任何一个单独开始都不影响**）：

```
P1 执行器层 ──┐
              ├──► P3 两轮自平衡车 ──►（延伸）智能小车 / 路径跟踪
P2 感知层 ────┘            │
                           └──► P4 倒立摆（选修，欠驱动）
P5 慢过程 MPC（完全独立，任何时间都能插空做）
```

- P2 的姿态解算代码，**原样**被 P3、P4 调用；
- P1 的 `motor.c` / `encoder.c` / 定时器框架，**原样**被 P3 调用；
- P5 与其余四个无依赖，可以第一个做。

## 4. 排期：不改你的 28 天计划，只加硬件

原计划每天一个仿真任务。硬件**并行**推进，关键是提前下单：

| 计划周 | 仿真进度（原计划） | 硬件动作 | 关键提醒 |
|---|---|---|---|
| 第 1 周 | PID + 滤波 | **立刻下单**第一批；到货前先把 P2 的互补滤波在 Python 里写完 | 算法在电脑上写，硬件在路上跑，别互相等 |
| 第 2 周 | 状态估计 KF / EKF | P1 完成整定与辨识；P2 做到二维 KF；**下单第二批** | 第 2 周末车架必须到手，否则第 3 周空转 |
| 第 3 周 | LQR + MPC | P3 串级 PID 立起来 → 换 LQR；P5 可与 P3 并行 | P3 卡住时 P5 是保底成果，两个方向都出数据 |
| 第 4 周 | 集成发布 | 把各项目的实测图并进主库 README；P4 写成「下一步计划」 | 硬件项目正好是 Day 27 那篇博客的素材 |

> 一句话：**算法在电脑上写，硬件提前买，到货就移植**。不要让「等快递」卡住 28 天节奏。

## 5. 统一工作流（每个项目都走这 5 步）

1. **仿真先行**：先在 `../src/` 用 Python 跑通算法，确定参数的**量级**。
2. **单点打通**：只验证一条信号通路（PWM 能转 / I2C 能读 / 编码器能计数），**不写控制**。
3. **开环记录**：控制器不参与，只记「输入 → 输出」的原始响应，这是你唯一的真实模型。
4. **闭环 + 采集**：加控制器，用上位机把 `设定值 / 实测值 / 控制量` 三条曲线录下来。
5. **对比与结论**：实测曲线和 Step 1 的仿真曲线叠一张图，写清差异原因（滞后、饱和、量化、摩擦）。

第 5 步是**唯一能写进简历的部分**，别跳过。

## 7. 四条硬规矩

1. **控制循环不许用 `HAL_Delay`**，一律定时器中断 + 固定周期。
2. **每个实验必须可复现**：记录固件版本、参数表、日期，数据落 CSV 存盘。
3. **上电前先想「失控会怎样」**：电机加护罩、手边有断电开关、倒地先断电再扶。
4. **先看曲线，再看平均值**：平均值漂亮但曲线在抖，等于没做。
