## 3. 建模（欠驱动的核心：控制量少于自由度）

状态 `x = [α, α̇, θ, θ̇]ᵀ`，其中 α 为摆臂角、θ 为摆杆角（**竖直向上为 0**）。

Furuta 摆的非线性方程（拉格朗日法得到，`J₁/J₂` 为转动惯量，`m,l` 为摆杆质量与质心距，`u` 为电机力矩）：

```
(J₁ + m l² sin²θ)·α̈ + ... = u − 阻尼项
J₂·θ̈ − m l² α̇² sinθ cosθ + m g l sinθ = 0
```

**做工程时你不需要手推全式**，两步走更快：

```python
import sympy as sp
# 用符号版拉格朗日推导, 再在 theta=0, alpha=0, 所有速度为 0 处线性化
# 得到 4x4 A 和 4x1 B, 丢给 scipy 求 K
```

```python
import numpy as np
from scipy.linalg import solve_continuous_are

# 线性化后的通用形式（具体系数代入你自己的 J1/J2/m/l/g）
A = np.array([[0, 1, 0, 0],
              [0, 0, a23, 0],
              [0, 0, 0, 1],
              [0, 0, a43, 0]])
B = np.array([[0], [b2], [0], [b4]])

Q = np.diag([1, 1, 20, 1])     # 摆杆角权重大, 它是首要目标
R = np.array([[1.0]])
K = np.linalg.solve(R, B.T @ solve_continuous_are(A, B, Q, R))
```

**这个系统是欠驱动的证据**：2 个自由度、1 个执行器。`B` 矩阵第二行有、第四行也有（通过耦合项），但**不能独立指定摆杆角**——你只能用摆臂的加速度去"甩"摆杆。这就是 LQR 在这里比 PID 好用的根本原因：**PID 是单回路思维方式，而 LQR 天然处理多状态耦合**。

## 4. 阶段一：能量起摆（swing-up）

直立时摆杆的能量是 `E₀ = 2 m g l`（以垂down为 0 势能点）。起摆就是**往摆杆里泵能量，直到 E = E₀**。

经典的能量控制律（Åström–Furuta）：

```
E  = 0.5·J₂·θ̇² + m·g·l·(cosθ − 1)        # 摆杆当前机械能
u  = k · (E − E₀) · sign(θ̇ · cosθ)        # 摆臂力矩指令
```

- `E < E₀` 时往摆杆里注入能量，`E > E₀` 时抽走；
- 力矩方向随「摆杆摆动相位」翻转，形成**共振式泵能**；
- `k` 从 100 起试，越大起摆越快但越暴力。

```c
/* 1 ms 中断 */
float E  = 0.5f*J2*thd*thd + m*g*l*(cosf(th) - 1.0f);
float E0 = 2.0f*m*g*l;
float u_swing = k_swing * (E - E0) * ((thd*cosf(th) > 0) ? +1.0f : -1.0f);
```

**起摆成功的关键在「切换时机」**，不在控制律本身：

| 条件 | 说明 |
|---|---|
| `|θ| < 15°` | 摆杆接近直立 |
| `|θ̇| < 60 °/s` | 且速度不大（太快冲过去） |
| 摆臂角速度 `|α̇|` 不大 | 否则切换瞬间会甩飞 |

满足即切 LQR，切的时候**清空积分、懒切换（保持 50 ms 再确认一次）**，避免在边界反复横跳。

**失败模式**：

| 现象 | 原因 | 处理 |
|---|---|---|
| 摆杆越甩越低 | 力矩方向反了 | `u` 取反（这是最常见的错） |
| 甩到 90° 附近就上不去 | 泵能量不够 / 摆臂行程不足 | 加大 `k`、加大摆臂行程或电机扭矩 |
| 到顶了但冲过头、来回甩 | 切换条件太松 | 收紧 `θ̇` 阈值 |
| 一直小幅摆动泵不上去 | 摩擦太大（铰链太紧） | **机械问题**，先修铰链，算法救不了 |

> **调试心法**：起摆阶段先只看到「摆杆幅度越来越大」就算成功，切换和 LQR 是下一个问题。**一次只解决一个问题。**

## 5. 阶段二：LQR 平衡

和 P3 一样的流程，但这里所有量都是编码器直接测的（角度、角速度都能差分得到，**不依赖 IMU**），所以**标定问题比 P3 小得多**。

```c
/* 1 ms 中断 */
float xs[4] = { enc_arm * ARM_SCALE,     /* 摆臂角, rad */
                enc_arm_vel,             /* 摆臂角速度 */
                enc_pend * PEND_SCALE,   /* 摆杆角, rad (竖直=0) */
                enc_pend_vel };
float u = 0;
for (int i = 0; i < 4; i++) u -= K_lqr[i] * xs[i];
motor_set_torque(u);                     /* 力矩模式, 不是 PWM 模式 */
```

三个工程要点：

1. **编码器零位标定**：摆杆竖直时读数必须是 0。装的时候对不准就用软件偏置（`θ = enc - θ_offset`，`θ_offset` 在上电静止时采样）。
2. **角速度别用差分**：1 ms 差分噪声巨大，用 10 ms 窗口的差分并加一阶低通，或者用编码器芯片自带的速度输出。
3. **力矩模式**：步进电机给「加速度指令」（脉冲频率变化），直流电机给「电流/占空比」。**LQR 的 u 是力矩，换算要一次标定**（同 P3 §7.1）。

## 6. 阶段三：MPC（Day 18–19 的落点）

倒立摆是本篇里最适合演示 MPC 的对象——因为**约束是真实存在的**：

| 约束 | 物理含义 |
|---|---|
| `|u| ≤ u_max` | 电机电流/力矩上限 |
| `|α| ≤ α_max` | 摆臂不能撞到限位 |
| `|θ| ≤ 15°` | 超出线性化范围，模型失效（这条最有意思） |

把 LQR 换成 MPC（离散模型、预测 N=20 步、采样 10 ms）：

- **无约束**时，MPC 的解会收敛到 LQR 的稳态增益 K——**这是个很好的验证实验**：跑一遍 MPC，看它的第一步输出是否等于 `-Kx`。能对上，说明你的 MPC 写对了。
- **有约束**时（力矩饱和），MPC 会提前"减速"，而 LQR 只会硬顶到饱和然后失控。**这个对比图就是 Day 19 想要的东西。**

F103 上算 N=20 的 QP 比较吃力，三条路：

| 路线 | 可行性 | 说明 |
|---|---|---|
| 无约束解析解 | ★★★★★ | `u = -(SᵀQS+R)⁻¹SᵀQ(⋯)`，一次矩阵乘，F103 完全够 |
| 简化 QP（投影梯度，10 次迭代） | ★★★☆ | 能处理力矩饱和，1 ms 环里勉强 |
| 电脑端 MPC + 串口下发 | ★★★★ | **推荐**：Python 跑 cvxpy，只把 `u` 发下去，延迟 20–50 ms 可接受 |

> **建议**：倒立摆上的 MPC 用「电脑端计算 + 串口下发」方案，能完整验证算法正确性，又不用跟 F103 的算力死磕。等算法对了，再考虑移植。

## 8. 方案 B（反应轮）的关键差异

如果你想走「机械最省事」的路线，反应轮倒立摆只用一根杆 + 一个电机 + 一个飞轮：

| 差异点 | 说明 |
|---|---|
| 角度来源 | **没有关节编码器**，角度完全靠 IMU（P2 的成果）→ 这是它唯一的痛点 |
| 控制量 | 电机力矩 → 飞轮角加速度 → 反作用力矩作用于杆 |
| 状态 | `x = [θ, θ̇, ω_f]`（杆角、角速度、飞轮转速）——**飞轮转速是个必须管的约束** |
| 核心难题 | **动量饱和**：飞轮一直加速才能维持平衡，转到极限就没辙了。解法：加一个「飞轮转速回中」的慢环（牺牲一点姿态精度换可持续性） |
| 建模 | 比 Furuta 简单得多，几乎就是一阶倒立摆 + 一个飞轮储能项 |
| 优点 | 结构极简、不用机加工、成本最低、失败风险最低 |
| 缺点 | 得靠 IMU（会漂）；飞轮饱和；控制权限小，抗扰弱 |

**如果你在 P3 已经把「IMU 姿态 + 电机」调通了，反应轮是性价比最高的「欠驱动入门」。**

## 9. 安全

- 摆杆甩起来是**真的会打到人**。必须加亚克力护罩，护罩和摆杆之间留 > 5 cm。
- 起摆阶段摆臂力矩最大，**底板必须螺栓固定在桌上**，否则整个装置会自己跳起来。
- 高速旋转部件（飞轮、联轴器）附近不要放手，长发扎起来。
- 手边必须有**急停**：一个常闭按钮串在驱动使能脚上，硬件断使能，不走软件。

## 10. 常见坑

1. **铰链有间隙** → LQR 永远高频抖。用轴承，不要用螺丝直接当轴。
2. **编码器分辨率不够**（比如 100 线）→ 摆角量化 0.9°，LQR 的 D 项全是台阶。至少要 600 线。
3. **起摆律符号反了** → 摆杆幅度越甩越小。这是第一个要试的。
4. **切换瞬间冲击** → 清积分 + 双帧确认。
5. **线性化范围误用** → 摆角 20° 时线性模型已经不准，LQR 会发散。切换条件和 LQR 的 `Q` 都要围绕小角度设计。
6. **摆臂限位没做** → 摆臂转到 360° 把线绞断。加机械挡块或软件限位。
7. **电机丢步（步进）** → 编码器读回来和指令对不上，控制全乱。用闭环驱动或降低加速度。
8. **桌面不水平** → 有个常值倾角偏置，LQR 的稳态误差永远存在。加积分或垫平桌子。
