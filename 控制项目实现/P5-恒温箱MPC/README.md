**一句话**：这是唯一一个「算法难度高、物理风险低」的项目。**P3 卡住的时候，它是你的保底成果。**

## 5. 阶段一：温度测量（先做这个，别急着写控制）

### 5.1 NTC 标定

NTC 的阻值-温度关系（Beta 公式）：

```
R(T) = R25 · exp(B · (1/T − 1/298.15))
T = 1 / (1/298.15 + ln(R/R25)/B)        ← 反解，单位 K
B = 3950, R25 = 10 kΩ
```

ADC 读的是分压电压：

```
R_ntc = 4.7k · V_adc / (3.3 − V_adc)
```

**必做**：用冰水混合物（0°C）和沸水（100°C，注意海拔修正忽略）各测一次，校准 `R25` 和 `B`。**不要相信标称值，误差能有 ±2°C。**

### 5.2 滤波（Day 3 的成果直接用上）

```c
/* 1 Hz 采样, 一阶低通 */
temp_f = 0.2f * temp_raw + 0.8f * temp_f;    /* alpha = 0.2, 等效 τ ≈ 4 s */
```

ADC 噪声在 12 位下约 ±3 LSB ≈ ±0.05°C，滤波后 < 0.02°C。**温度信号本身很慢，滤波不会引入有害滞后**——这是滤波器最舒服的应用场景（和平衡车正好相反）。

## 6. 阶段二：FOPDT 辨识（整个项目的基石）

### 6.1 实验

关掉控制，给**恒定 60% 功率**加热 15 分钟，记录温度到稳态或安全上限。记录 `t, temp, duty`。

### 6.2 拟合

```python
import numpy as np, pandas as pd
from scipy.optimize import curve_fit

df = pd.read_csv("p5_step.csv")
t, y = df.t.values, df.temp.values
u0, y0 = 0.6, y[0]
du = u0 - 0.0

def fopdt(t, K, T, tau):
    # 一阶惯性 + 纯滞后
    return np.where(t < tau, y0,
                    y0 + K*du*(1 - np.exp(-(t - tau)/T)))

popt, pcov = curve_fit(fopdt, t, y, p0=[50, 120, 15],
                       bounds=([1, 5, 0], [500, 2000, 300]), maxfev=50000)
K, T, tau = popt
print(f"K = {K:.1f} °C/unit, T = {T:.1f} s, tau = {tau:.1f} s")
# 拟合质量
yhat = fopdt(t, *popt)
r2 = 1 - np.sum((y-yhat)**2)/np.sum((y-y.mean())**2)
print(f"R^2 = {r2:.4f}")
```

**典型值**：小箱子 `K ≈ 40–80 °C/单位`，`T ≈ 60–200 s`，`τ ≈ 5–30 s`。

**如果 R² < 0.95**，说明有非线性（散热与温度差成正比、加热器功率随温度变化），两个处理：

1. 在**工作点附近**（比如 35–45°C）做小阶跃（60%→70%），辨识局部线性模型——MPC 用局部模型反而更准；
2. 或者接受它是 FOPDT 近似，在 MPC 里保留积分项补偿。

## 7. 阶段三：PID 基线

```c
/* 1 Hz */
float e = temp_ref - temp_f;
integ += ki * e;  /* 限幅 0..1 */
float u = kp*e + integ + kd*(e - e_prev);
u = clamp(u, 0.0f, 0.95f);
```

**PID 在这类对象上的典型表现**（你要观察并记录）：

- Ki 小了 → 永远差 2°C；
- Ki 大了 → 因为 τ 存在，**必超调 3–8°C**，然后慢慢回来；
- 想不超调就得压慢 → 到达时间翻倍。

**这就是 MPC 要解决的那个 trade-off**，把它记下来当对比基线。

## 8. 阶段四：MPC（本项目的核心）

### 8.1 模型离散化 + 增量形式

把连续模型 `K·e^{-τs}/(Ts+1)` 零阶保持离散，采样 `Ts = 2 s`（比 T 小一个数量级，比 τ 小很多倍），滞后折算成整数步 `d = round(τ/Ts)`。

为了**消除稳态误差**，用增量输入 `Δu`：

```
Δx(k+1) = A·Δx(k) + B·Δu(k)
y(k+1)  = y(k) + C·A·Δx(k) + C·B·Δu(k)

增广状态  z(k) = [Δx(k); y(k)]
z(k+1) = Az·z(k) + Bz·Δu(k),   Az = [[A, 0], [C·A, 1]],  Bz = [B; C·B]
```

### 8.2 预测与代价

预测 N 步（N 要盖住滞后 + 一个时间常数：`N·Ts > τ + T`，所以 **N ≈ 20–30**）：

```
Y = F·z(k) + Φ·ΔU,      ΔU = [Δu(k), ..., Δu(k+N−1)]ᵀ
```

代价函数（`R` = 设定值轨迹）：

```
J = (Y − R)ᵀ·Q·(Y − R) + ΔUᵀ·Ru·ΔU
```

### 8.3 无约束解 → 一个常数反馈矩阵（**关键洞察**）

```
ΔU* = (ΦᵀQΦ + Ru)⁻¹ · ΦᵀQ · (R − F·z)

取第一行:
Δu(k) = K_mpc · (R − F·z)
```

**因为 Q、Ru、Φ、F 都是离线可知的常数，`K_mpc` 和 `F` 也是常数**——所以**无约束 MPC 在嵌入式上就退化成一个固定的状态反馈**，每次只做一次矩阵乘加。**这让 F103 完全跑得动，也解释了为什么 MPC 和 LQR 在没有约束时效果几乎一样**（Day 19 的对比结论就是这个）。

### 8.4 带约束 → 需要在线 QP

约束：

```
0 ≤ u(k+j) ≤ u_max            （功率限制）
u 的变化率  |Δu| ≤ Δu_max      （防止继电器式猛开猛关）
y(k+j) ≤ 60°C                  （安全上限）
```

代进 `ΔU`：

```
min  ½·ΔUᵀ·H·ΔU + fᵀ·ΔU
s.t. A_c·ΔU ≤ b_c
      H = ΦᵀQΦ + Ru,   f = ΦᵀQ(F·z − R)
```

**F103 上的实现预算**（1 Hz，N=20）：

| 方案 | 每步运算量 | 结论 |
|---|---|---|
| 投影梯度法，50 次迭代 | ~20×20 矩阵乘 ×50 ≈ 2×10⁴ 次乘加 | **可行**（1 Hz 有 7200 万周期预算） |
| 主动集法 | 变量少时更快 | 可行但代码复杂 |
| 离线 QP + 在线查表 | 显式 MPC，需要预计算 | 内存吃紧（64 KB） |
| **电脑端算 + 串口下发** | MCU 只收 u | **推荐先做这个，验证算法后再移植** |

### 8.5 代码骨架（移植版）

```c
/* 离线算好的常数 */
static const float Kmpc[N] = { ... };      /* (ΦᵀQΦ+Ru)⁻¹ΦᵀQ 的第一行 */
static float z[2];                         /* z = [Δx, y] */

void mpc_step_1hz(void)
{
    /* 1. 组装 z */
    z[0] = temp_f - y_prev;                /* Δy */
    z[1] = temp_f;

    /* 2. 计算未约束的 Δu */
    float du = 0.0f;
    for (int i = 0; i < N; i++) { /* Y_pred 递推 */ }
    /* 简化: 直接 du = Kmpc · (R - F·z), F 也可离线打成常数 */

    /* 3. 投影到约束集（这就是"带约束"的全部代价） */
    du = clamp(du, -du_max, du_max);
    u_next = clamp(u_prev + du, 0.0f, u_max);

    /* 4. 输出 */
    pwm_set(u_next);
    u_prev = u_next;
}
```

> **注意第 3 步**：只对「当前步」做投影是**简化版（sub-optimal）**，严格做法要对整个 `ΔU` 向量解 QP。但对温控这种慢对象，简化版效果已经足够，**而且实现只要 3 行**。先用它跑通，再考虑真 QP。

## 9. 对比实验（本项目的「结论」）

同一台设备、同一目标（25°C → 45°C），三种控制器各跑一次：

| 控制器 | 到达时间 | 超调 | 稳态误差 | 违反约束次数 |
|---|---|---|---|---|
| PID（激进整定） | 快 | **大** | 小 | 0 |
| PID（保守整定） | 慢 | 小 | 可能大 | 0 |
| MPC（无约束） | — | — | — | — |
| **MPC（带约束）** | 快 | **接近 0** | 小 | **0** |

**预期的漂亮结论**：MPC 同时拿到「激进 PID 的速度」和「保守 PID 的超调」——因为它在预测到要超调时会提前减功率。**这张图 + 这句话，就是这个项目全部的价值。**

加分实验：把 `y ≤ 43°C` 当硬约束，让目标设成 45°C。PID 会冲到 45（违反约束），MPC 会停在 43 并在可行域内尽量逼近——**这是「约束」两个字的直接可视化**。

## 10. 安全（**这个项目的风险是火灾，认真读**）

1. **硬件过温保护必须独立于 MCU**：KSD 温控开关（常闭，50°C 断开）串在加热回路里。MCU 死机时它仍然工作。
2. **加热片必须贴在金属上**（铝块/散热片），不能悬空或贴塑料。
3. **箱子用亚克力或金属，绝不用纸盒/泡沫**。
4. **限温 60°C**，软件里写死上限，任何目标值都不能超过它。
5. 人离开房间时**断电**。
6. 有烟雾/异味立即断电——NTC 掉了（接触不良）会让控制环误以为温度低而全功率加热，**这是最危险的单点失效**。对策：加一路 DS18B20 作为独立监测，两路温度差 > 5°C 就切断。
7. 保险丝选 2 A（12 V × 2 A = 24 W，匹配 20 W 加热片）。

## 11. 常见坑

1. **辨识时没到稳态就拟合** → T 估小了，MPC 预测偏乐观 → 超调。
2. **滞后 τ 被忽略** → 这是 PID 超调的根源，也是 MPC 唯一不可省的参数。τ 用「加热开始到温度开始上升」的时间差直接量。
3. **采样周期 2 s 但 `dt` 写成 1 s** → 模型增益错一倍，全部失效。
4. **NTC 自热**：流过 NTC 的电流大会自己发热。串 4.7k 上拉 + 3.3 V 时电流约 0.2 mA，功耗 0.4 µW，可忽略——但别用 100 Ω 上拉。
5. **MOSFET 不发热但也不工作**：用了非逻辑电平的 IRF520，3.3 V 栅压开不透，进入线性区 → **又热又不通**。必须用 IRLB8721/IRLR7843 这类 `Vgs(th) < 2V` 的。
6. **PWM 频率太低**（如 10 Hz）→ 加热片有吱吱声、温度纹波大。用 1 kHz。
7. **没做抗积分饱和** → 从 25°C 升到 45°C 时积分早爆了，到 45°C 后继续加热冲过头。用「饱和时停积分」。
8. **环境温度变化** → 冬天和夏天同一参数表现不同。MPC 的积分项能吃掉一部分，但要记录环境温度。
9. **用继电器代替 MOSFET** → 开关寿命有限、有火花、无法 PWM。**必须用 MOSFET**。
10. **只测一个点** → 加热片附近的温度比箱内中心高很多，测点位置决定了你控制的是什么。把 NTC 放在箱内**中心**、远离加热片。

## 13. 延伸

- **双向控制**：加风扇，把「只能加热」变成「能加热也能制冷」，MPC 的优势更明显（可以主动降温）。
- **多变量**：两个加热区、两个传感器 → 这才是 MPC 真正超过 PID 的地方（MIMO 解耦）。
- **自适应**：在线更新 `K` 和 `T`，做「自校正 MPC」（进阶，与 Day 17 的 LQR 灵敏度分析呼应）。
- **移植到 P3**：把这套 MPC 框架挪到平衡车上（受限算力，需降 N 或显式 MPC）。
