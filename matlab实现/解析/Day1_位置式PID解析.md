## 一、整段代码在干什么（一句话版）

在电脑里「模拟」一个真实的一阶惯性系统，接上一个 PID 控制器，看它能不能从 0 追到设定值 1。因为只是模拟，所以不需要真实硬件，只需要一个 `for` 循环一步一步推演。

---

## 二、为什么这么写（逐段）

### 1. 为什么一开头是 `clear; clc; close all;`

```matlab
clear; clc; close all;
```

- `clear`：清空工作区里之前残留的变量。否则上一次运行留下的 `x`、`y` 会污染这次结果。
- `clc`：清空命令行窗口，看输出干净。
- `close all`：关掉之前打开的图窗口，避免新图和旧图叠在一起。

> 这是 MATLAB 脚本的「标准开场三连」，几乎每个脚本都这么写。

### 2. 为什么 `dt = 0.001` 这么小

```matlab
dt       = 0.001;     % 控制周期 1ms
duration = 10.0;      % 仿真 10 秒
t        = 0:dt:duration;
n        = length(t);
```

控制是**连续时间**的事（微分方程 `dx/dt = ...`），但电脑只能**离散**地一步一步算。`dt` 就是每步之间的时间间隔：

- `dt` 越小 → 每步跨的时间越小 → 离散近似越接近真实的连续系统（更准），但步数变多、跑得慢。
- `dt` 太大 → 会算错，甚至数值发散（比如系统振荡，`dt` 取 0.1 就完全失真）。

`0.001` 秒（1ms）是个折中：对慢系统够准，又不会太慢。`t = 0:dt:duration` 是 MATLAB 生成等间隔数组的写法，等价于 Python 的 `np.arange(0, duration+dt, dt)`。

> 注意：`t = 0:dt:duration` 会生成 `0, 0.001, ..., 10.000` 共 `n = 10001` 个点。所以 `length(t)` = 10001，不是 10000，因为头尾都算。

### 3. 为什么被控对象写成 `dx/dt = -a*x + b*u`，又为什么要「离散化」

```matlab
a = 1.0;
b = 0.3;
```

这是「一阶惯性环节」的微分方程。它描述一个常见的物理对象：给一个输入 `u`，输出 `x` 不会立刻跳变，而是指数地、缓慢地逼近某个值（就像 RC 电路充电、热水器升温）。

电脑不能直接算微分，所以用**前向欧拉法**把它变成差：

```
连续:  dx/dt = -a*x + b*u
离散:  x[k+1] = x[k] + dt * (-a*x[k] + b*u[k])
                        ^^^   这一步就是"用一小步斜率去外推"
```

对应代码：

```matlab
x = x + dt*(-a*x + b*u(k));
```

这就是整个仿真最核心的一行——**每拍用当前状态算变化率，再往前迈一小步**。

### 4. 为什么 PID 的积分是「累加」、微分是「后向差分」

位置式 PID 的连续公式：

```
u(t) = Kp*e(t) + Ki*∫e dτ + Kd*de/dt
```

到离散世界，积分和微分分别用「累加」和「相邻两拍之差」来近似：

| 连续项 | 离散近似 | 代码 |
|---|---|---|
| 积分 `∫e dτ` | 累加和 `Σ e·dt` | `integral = integral + e*dt;` |
| 微分 `de/dt` | 后向差分 `(e[k]-e[k-1])/dt` | `derivative = (e - e_prev)/dt;` |

为什么积分要乘 `dt`？因为「累积面积」= 高度 × 宽度，`e` 是高度，`dt` 是每小条的宽度。漏掉 `dt` 会导致积分项的数值随 `dt` 变化，换个采样周期就得重调 Ki。

### 5. 为什么循环里「先记录 y、再算 u、再更新对象」

```matlab
for k = 1:n
    y(k) = x;                       % ① 记录当前输出
    e    = setpoint - y(k);         % ② 算误差
    ...
    u(k) = kp*e + ki*integral + kd*derivative;  % ③ 算控制量
    x = x + dt*(-a*x + b*u(k));     % ④ 用控制量更新对象
    e_prev = e;                     % ⑤ 更新误差记忆
end
```

这个顺序对应真实控制循环的因果逻辑：

1. **测量**：先知道现在系统在哪（`x`）→ 这就是 `y(k)`
2. **比较**：设定值减去测量值 = 误差
3. **决策**：PID 根据误差算出该给多大的力 `u(k)`
4. **执行**：把 `u(k)` 作用到对象上，对象状态前进一拍
5. **记账**：保存这拍的误差，供下一拍算微分

顺序不能乱——尤其 `u(k)` 必须**用当前这一拍的误差**，而对象更新必须**用当前这一拍的控制量**，这就是「因果」：先有果（测量），才有因（决策）。

### 6. 为什么每组参数都要重新初始化状态

```matlab
for c = 1:3
    ...
    x = 0;  integral = 0;  e_prev = 0;   % 每轮清零
```

三组参数（P only / PI / PID）是**三次独立的实验**，各用各的干净系统。如果不清零，第二组会接着第一组跑完的状态继续，积分累加器里还留着上一轮的值，曲线就串了。

### 7. 为什么用 `subplot(2,1,1)` 和 `hold on`

```matlab
subplot(2,1,1); hold on; grid on;
```

- `subplot(2,1,1)`：把图分成 2 行 1 列，当前在第 1 格画（上面那格）。第 2 格是下面那格。
- `hold on`：**关键**——不写它的话，画第二条 `plot` 时会把第一条擦掉。三条曲线（P only / PI / PID）要叠在同一张图上对比，所以必须先 `hold on`。
- `grid on`：加网格，方便读数。

> 对应 Python 的 `fig, (ax_y, ax_u) = plt.subplots(2,1)`。Python 里每个 `ax` 独立，天生能叠画；MATLAB 里同一个 `subplot` 要叠画必须靠 `hold on`。

### 8. 为什么设定值用 `yline` 画，而不是 `plot`

```matlab
yline(setpoint, 'k--', 'setpoint');
```

设定值是一条**水平直线**（恒等于 1），`yline(1)` 就是「画一条 y=1 的水平线」，比 `plot(t, ones(1,n))` 更简洁。`'k--'` 是「黑色 + 虚线」，区分于三条实线曲线。`'setpoint'` 是这个线在图例里的名字。

### 9. 为什么 `plot` 里的 `'DisplayName', names{c}` 能直接出图例

```matlab
plot(t, y, 'DisplayName', names{c});
...
legend('show');
```

MATLAB 的 `plot` 支持 `'DisplayName'` 参数给曲线起名，之后 `legend('show')` 会自动把这些名字收进图例。这比 Python 的 `ax.plot(..., label=...)` + `ax.legend()` 是同一套逻辑，只是关键词从 `label` 换成了 `DisplayName`。

## 三、看懂图：怎么从曲线读参数作用

跑完这张图你会看到（和 `docs/images/day1_position_pid.png` 一致）：

- **P only**：输出升到某个值就停住了，**到不了 1**，有「稳态误差」。因为纯比例控制「误差为 0 时控制量也为 0」，而要让系统停在 1 需要持续给力，所以矛盾，只能停在中间。
- **PI**：积分项把误差一点点「攒」起来，最终把输出顶到 1，**消除稳态误差**。
- **PID**：对一阶系统，D 几乎没区别——因为一阶系统本身不振荡，D 的价值要等 Day 2 的二阶振荡系统才看得见。

这就是为什么要画图：**调参的直觉是「看」出来的，不是「算」出来的。**
