# Day 5 互补滤波 —— 代码逐段解析

> 对应代码：`代码/day5_complementary_filter.m`
> 对应 Python：`examples/day5_complementary_filter.py`
> 这张图要回答的问题：**两个传感器的毛病正好互补，怎么把它们拼成一个靠谱的角度？**

---

## 一、先讲透：公式只有一行，但要拆成两步看

```
angle[k] = α·(angle[k-1] + gyro[k]·dt) + (1-α)·angle_acc[k]
```

```
① 预测（信陀螺，短时间准）：pred = angle[k-1] + gyro[k]·dt
② 修正（信加速度计，长期准）：angle[k] = α·pred + (1-α)·angle_acc[k]
```

**α 是陀螺的权重，`1-α` 是加速度计的权重，两者加起来是 1。**

展开一下会看到一个更重要的结构：

```
angle[k] = pred + (1-α)·( angle_acc[k] − pred )
                      ↑ 增益 K          ↑ 残差（测量 − 预测）
```

**这就是一个固定增益的观测器。** Day 9 的卡尔曼滤波是同一个式子，只是把 `(1-α)` 换成随协方差自动变化的 `K`。

---

## 二、为什么这么写（逐段）

### 1. 为什么纯陀螺积分用 `cumsum`，而互补滤波要写 for 循环

```matlab
ang_gyro = [0, cumsum(gyro(2:end))*dt];      % 纯陀螺积分
```

`cumsum` 是累积求和，一次算完整个积分：

```
ang_gyro[k] = gyro[1]·dt + gyro[2]·dt + ... + gyro[k]·dt
```

`[0, ...]` 是把结果整体右移一格，让积分从 0 开始（第 1 个采样点不累加）。这一步和 Python 版里的
`angle_gyro[k] = angle_gyro[k-1] + gyro[k]*dt` 完全等价，只是向量化写法更快。

但互补滤波**不能**这样写，因为它有递推：

```matlab
ang(k) = alpha*pred + (1-alpha)*accel(k);     % pred 依赖 ang(k-1)
```

第 k 拍要用第 k−1 拍的输出，`cumsum` 表达不了，只能老老实实写循环（封装成局部函数 `cf_run`）。

> **为什么这么写**：能向量化就向量化（积分），有递推就循环（滤波器）。这也是 MATLAB 写滤波器的通用取舍。

### 2. 为什么 α 既是"陀螺权重"，又是"低通系数"的另一半

加速度计那一路的传递函数：

```
H_acc(z) = (1-α) / (1 − α·z⁻¹)
```

对照 Day 3 的一阶低通 `y[k] = α'·x[k] + (1-α')·y[k-1]`，令 **α' = 1-α** 就完全一致。

所以 `cf_consts` 里那句：

```matlab
a   = 1 - alpha;                 % 加速度计那一路的低通系数 α'
tau = dt*alpha/a;                % τ = dt·α/(1-α)
```

就是 Day 3 的 `τ = dt·(1-α')/α'` 换了个名字。**同一个公式，只是 α 的含义反过来了**：

| | 公式 | α 是谁的权重 |
|---|---|---|
| Day 3 一阶低通 | `y = α·x + (1-α)·y_prev` | 新样本 |
| Day 5 互补滤波 | `angle = α·pred + (1-α)·accel` | 历史预测（陀螺） |

**这是抄公式时最容易翻车的地方**，写代码前先问自己"我要放大的是哪一路"。

### 3. 为什么 fc 也要用 Day 3 那个精确式，而不用 `fc ≈ 1/(2πτ)`

```matlab
c  = (2 - 2*a - a^2) / (2*(1 - a));
fc = acos(c) / (2*pi*dt);
```

因为本课 `dt = 10 ms`（100 Hz）、`fc ≈ 0.32 Hz` 已经非常接近直流，近似式在这里误差不大——但**同样的代码在 200 Hz 采样时就要用精确式**，所以直接复用 Day 3 的写法，不用改。

本课结果：`τ = 0.490 s`、`fc = 0.32 Hz`。

### 4. 为什么 `rng(0)` 和 Python 的 `default_rng(0)` 不一样

两边都固定了种子，但**两个软件的随机数发生器不同**，所以生成的噪声序列不一样。后果：

- 图看起来几乎一样，但 RMSE 会有小数点后的差别（Python 版一阶 RMSE 0.1448，MATLAB 版 0.1419）；
- 结构性结论（超调 4.32%、延迟 3.98 ms、−10.7 dB）**完全一致**，因为这些只由系数决定，与噪声无关。

> **为什么这么写**：固定种子是为了「同一软件内可复现」，不是为了「跨软件一致」。跨软件要对齐的是**结构和结论**，不是某一次抽样的具体数值。

### 5. 为什么 (c) 的 y 轴用 `semilogy`

```matlab
semilogy(alphas, scan, 'b', 'LineWidth', 1.8);
```

RMSE 在 α 变大的后半段会**陡峭崩塌**（0.27 → 0.97），线性坐标下前半段的细节会被压扁。取对数后，「左边缓、右边崩」这个形状才看得清——而这个形状正是调参时最需要的直觉：**α 宁小勿大**。

### 6. 为什么 (d) 画的是 `|H_lp|` 和 `|H_hp|`

```matlab
Hlp = (1 - alpha) ./ (1 - alpha*exp(-1j*w));
Hhp = 1 - Hlp;
```

`Hhp = 1 - Hlp` 这个减法是核心：**不是另一条独立的曲线，而是"补"出来的**。

```
H_lp(z) + H_hp(z) ≡ 1      ← 任何频率都成立
```

- 低频（z→1）：`H_lp = 1, H_hp = 0` → 信加速度计；
- 高频（z→−1）：`H_lp ≈ 0, H_hp ≈ 1` → 信陀螺；
- 中间在 `fc` 附近交叉。

**这就是"互补"两个字的严格含义**，也是 (d) 这张图存在的理由——它把"为什么叫互补滤波"画成了一张图。

### 7. 为什么把 `cf_run` 和 `cf_consts` 放成局部函数

```matlab
function ang = cf_run(gyro, accel, alpha, dt, a0)
function [tau, fc] = cf_consts(alpha, dt)
```

两处都复用：`cf_run` 在三种估计和 α 扫描里各调一次（扫描要调 60 次），`cf_consts` 在两处用到 τ/fc。

R2016b 之后脚本末尾可以定义局部函数，好处是主流程只剩「参数 → 数据 → 三种估计 → 出图」，读起来和 Python 版的 `main()` 结构一致，方便对照。

## 三、看懂图：四个面板各看什么

- **(a)**：灰线（加速度计）一直抖但不跑偏；红线（陀螺积分）前几秒贴得很紧，然后一路飘到 +30°（末态偏 14.8°）；蓝线（互补）既贴真值、又几乎没毛刺。
- **(b)**：这张更直接——红线是**一条斜直线**，斜率就是零偏 0.5 °/s；灰线在 ±3° 带里抖但均值为 0；蓝线贴着 0，幅度小一个数量级。
- **(c)**：α 太小（0.9）→ 噪声进来，RMSE 0.35；α 太大（0.995）→ 跟不住运动，RMSE 0.97；最优 α≈0.961，RMSE 0.27；课本值 0.98 只差 13%。
- **(d)**：蓝线（低通）从 1 掉到 0，橙线（高通）从 0 升到 1，在 `fc = 0.32 Hz` 交叉，两条加起来恒为 1。

## 四、Python 与 MATLAB 的对应关系

| Python | MATLAB |
|---|---|
| `ComplementaryFilter.update(gyro, accel)` | `cf_run(gyro, accel, alpha, dt, 0)` |
| `cf.tau` / `cf.cutoff_hz` | `cf_consts(alpha, dt)` 返回 `[tau, fc]` |
| `angle_gyro[k] = angle_gyro[k-1] + gyro[k]*dt` | `[0, cumsum(gyro(2:end))*dt]` |
| `accel_path_response(alpha, dt, f)` | `Hlp = (1-alpha)./(1-alpha*exp(-1j*w))` |
| `for k: cf.update(...)` 逐拍循环 | `cf_run` 内部同样是 for 循环 |

**唯一的结构差别**：MATLAB 版把互补滤波封成一个函数一次性算完（因为递推无法向量化），Python 版保留"一拍一输入"的 `update()` 接口——**那个接口后面要直接搬到 STM32 的定时器中断里用**（P2 姿态解算就是这么做的）。
