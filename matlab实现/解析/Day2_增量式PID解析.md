# Day 2 增量式 PID —— 代码逐段解析

> 对应代码：`代码/day2_incremental_pid.m`
> 对应 Python：`examples/day2_incremental_pid.py`
> 这张图要回答的问题：**增量式 PID 和位置式 PID 到底差在哪？**

---

## 一、先讲透：两种 PID 的公式差在哪

### 位置式 PID（输出绝对控制量）

```
u[k] = Kp*e[k] + Ki*I[k] + Kd*D[k]
       其中 I[k] = I[k-1] + e[k]*dt   ← 有一个"积分累加器"会一直涨
       其中 D[k] = (e[k] - e[k-1]) / dt
```

### 增量式 PID（输出控制量的"增量"）

对位置式做一阶差分，**消掉了积分累加项**，得到：

```
Δu[k] = Kp*(e[k] - e[k-1])
      + Ki*e[k]*dt                        ← 乘 dt
      + Kd*(e[k] - 2*e[k-1] + e[k-2])/dt   ← 除 dt

u[k] = u[k-1] + Δu[k]
```

**这两个 dt 因子不能省，这是 Day 2 最容易踩的坑。**

很多教材把它写成 `Kp*Δe + Ki*e[k] + Kd*Δ²e`，把 dt 省掉了。那种写法本身没错，但式子里的
Ki、Kd 已经**不是连续域增益**了，而是提前吸收了采样周期的系数：
Ki = Kp·T/Ti，Kd = Kp·Td/T。

两套写法的**数字不能混用**。如果拿位置式那一组 kp/ki/kd 直接套进省掉 dt 的式子，
积分增益就被放大 1/dt 倍（本例 dt=0.01，等于放大 100 倍），闭环极点跑出单位圆，
仿真会一路发散到 1e11——图 (a)(b) 会变成一条贴着 0 的线加一条冲出屏幕的线。

> 这个坑真实存在于本仓库的历史版本里：Python 的 `IncrementalPID` 和 MATLAB 的
> `sim_incremental` 一开始都漏了 dt，`docs/images/day2_incremental_pid.png` 那张参考图
> 也是发散的（纵轴 1e9）。现在两边都已配平，和位置式共用同一组增益，
> 两条曲线在数值上完全重合（逐点误差 7e-15）。

对应代码（`sim_incremental` 函数里）：

```matlab
du = kp*(e - e_prev) + ki*e*dt + kd*(e - 2*e_prev + e_prev2)/dt;
u(k) = u_last + du;
```

**核心区别就一句话**：位置式有积分累加器（会无限累积），增量式没有——它唯一的「记忆」就是上一次输出 `u_last`，而 `u` 被限幅夹住，所以积分永远涨不起来。这就是「天然抗积分饱和」的来源。

## 二、必须先纠正的一个误解：增量式并不能消除「微分冲击」

这是 Day 2 原来写错的地方，值得单独拎出来。

「微分冲击（derivative kick）」指的是：设定值在某一刻阶跃（比如从 0 跳到 1），
误差 e 也瞬间跳变，微分项 `Kd·Δe/dt` 里那个 `Δe` 在这一拍非常大，再除以很小的 dt，
控制量 u 就被猛地顶出一个尖峰。

**关键在于：这个尖峰来自「对误差求导」这个动作，跟用位置式还是增量式实现没有关系。**

增量式本来就是位置式做一阶差分来的，只要 dt 因子配平，两者就是**严格的代数恒等式**。
所以设定值阶跃时，两者的 u 会在同一拍跳出**一模一样的尖峰**。实测：

| 指标 | 位置式 | 增量式 |
|---|---|---|
| t=0 第一拍的控制量 u | 33.02 | 33.02 |
| 全程 max abs(u) | 33.02 | 33.02 |
| 全程 max abs(y) | 1.1965 | 1.1965 |

图 (b) 里确实有一根很高的尖峰（纵轴到 33），但它不是「位置式专属」的——两条曲线
在那里完全重叠，肉眼看就是一条线。

**真正的解法是「微分先行」**：让 D 项作用在**测量值 y** 上，而不是作用在误差 e 上。

```
D[k] = -Kd * (y[k] - y[k-1]) / dt      ← 对测量值求导，设定值突变时不产生冲击
```

这样设定值阶跃时 y 是连续的，D 项不会跳变，尖峰自然消失。本仓库
`控制项目实现/P1-直流电机速度闭环/README.md` 里那段 STM32 代码用的就是这个办法，
注释写得很清楚：「微分先行: 对测量值求导, 设定值突变时不产生微分冲击」。

> 顺带一提：图 (a) 里两条曲线完全重合，也是同一个原因——配平之后两者等价。
> 如果哪天你看到它们分开了，先怀疑增益没配平，而不是怀疑算法有本质区别。

**那增量式到底赢在哪？** 只有一条，但很实在：**天然抗积分饱和**，另外附带无扰动切换
的好处。这正是图 (c)(d) 演示的东西，而且那个对比是真实的、幅度很大。

## 三、为什么这么写（逐段）

### 1. 为什么 Day 2 把代码拆成了好几个函数，而不是 Day 1 那样全写在一个脚本里

```matlab
[t1, r1, y_pos, u_pos] = sim_position(...);
[t1, ~, y_inc, u_inc] = sim_incremental(...);
...
function [t, r, y, u] = sim_position(...)   % 脚本末尾
```

因为 Day 2 要跑 **4 个面板、2 种 PID、2 种被控对象**，如果全摊平写，同一个 PID 公式要复制粘贴 4 遍，改一个参数就要改 4 处，极易漏。

所以把「重复的活」抽成函数：

| 函数 | 对应 Python 里的什么 | 干什么 |
|---|---|---|
| `sim_position` | `PositionPID` / `NaivePositionPID` + `simulate` | 跑一次位置式 PID 仿真 |
| `sim_incremental` | `IncrementalPID` + `simulate` | 跑一次增量式 PID 仿真 |
| `plant_step` | `FirstOrderPlant` / `SecondOrderPlant` | 被控对象前进一步 |
| `current_setpoint` | `current_setpoint` | 查当前时刻的设定值 |

> 这正好对应 Python 里的「类」和「函数」：Python 用 `class` 存状态 + `update` 方法，MATLAB 用「脚本末尾的 local function」实现同样的封装。**这是 MATLAB 里把长脚本组织起来的惯用写法**（函数放在脚本最后，MATLAB R2016b 之后支持）。

### 2. 为什么「二阶系统」要写成两个一阶状态 `x` 和 `v`

```matlab
function [x, v] = plant_step(u, x, v, dt, zeta, wn, b)
v = v + dt*(-2*zeta*wn*v - wn^2*x + b*u);
x = x + dt*v;
end
```

二阶微分方程 `x'' + 2ζωₙx' + ωₙ²x = b·u` 含有二阶导数，而「一阶递推」只能处理一阶。标准技巧是**引入速度 `v = x'`，把二阶方程拆成两个一阶方程**：

```
x'  = v                              ← 位置的变化率 = 速度
v'  = -2ζωₙv - ωₙ²x + b·u            ← 速度的变化率 = 加速度
```

所以代码里 `v` 先更新（用加速度），`x` 再用新 `v` 更新（用速度）。这就是为什么 `plant_step` 里 `v` 那行在 `x` 那行**之前**。

> 为什么 Day 2 要用二阶系统？因为**只有会振荡的系统才能体现微分项 D 的价值**——D 提供的是「刹车力」，一阶系统本来就单调爬升、没有振荡可刹车，看不出 D 有什么用。

### 3. 为什么 `plant_step` 传 `zeta=1, wn=1, b=1` 就是个「简单被控对象」

```matlab
sim_position(setpoint_seq, duration, dt, kp, ki, kd, 1.0, 1.0, 1.0, limits, false)
                                                      ^^^  ^^^  ^^^  zeta, wn, b
```

把 ζ=1、ωₙ=1、b=1 代入：

```
v' = -2·1·1·v - 1²·x + 1·u = -2v - x + u
x' = v
```

这是**阻尼比 ζ=1 的临界阻尼二阶系统**——它会「慢慢逼近、绝不超调」，但请注意：

> **它不是一个一阶系统。** `plant_step` 永远走二阶那条路，没有任何「一阶分支」。
> 之前这里的注释写成了「退化成一阶惯性环节」，那是错的，会让人以为 `plant_step`
> 里有条件判断。实际做法只是**偷懒复用同一个 `plant_step`**，用一组特定参数凑出一个
> 不振荡的对象，免得再写一个 `plant_1st` 函数。

和 Python 版 `FirstOrderPlant`（`dx/dt = -x + u`，真正的一阶）相比，两者在慢速近似下
行为接近，但**数值上并不完全相同**，所以 MATLAB 版 (c)(d) 的曲线和 Python 参考图会有
细微差别，结论（谁抗饱和、谁不抗饱和）则完全一致。

> 如果你觉得这个「复用」不直观，完全可以单独写一个一阶 `plant_step`，结果一样。
> 这里这样写只是为了代码更短。

### 4. 为什么用 `antiwindup` 开关来切换「有抗饱和 / 无抗饱和」

面板 (c)(d) 要同时演「有抗饱和」和「无抗饱和」两种位置式，于是 `sim_position` 多了一个开关：

```matlab
function [t, r, y, u] = sim_position(setpoint_seq, duration, dt, ...
                                     kp, ki, kd, zeta, wn, b, limits, antiwindup)
if nargin < 10
    limits = [];        % 默认不限幅
end
if nargin < 11
    antiwindup = true;  % 默认带条件积分抗饱和
end
```

限幅与积分更新的核心逻辑：

```matlab
if isempty(limits)
    integral = integral_candidate;
elseif u(k) > limits(2)
    u(k) = limits(2);                    % 被限幅
    if ~antiwindup
        integral = integral_candidate;   % 无抗饱和：饱和时积分照涨
    end
elseif u(k) < limits(1)
    u(k) = limits(1);                    % 被限幅
    if ~antiwindup
        integral = integral_candidate;
    end
else
    integral = integral_candidate;       % 未饱和才累积积分
end
```

关键在 `antiwindup` 为真时的那两个「什么都不做」：

- **有抗饱和**（`antiwindup = true`）：输出一旦被限幅，就**不更新积分**，积分停在最后那个值，不会继续疯涨。
- **无抗饱和**（`antiwindup = false`，面板 (c)(d) 要演示的坏情况）：积分**无条件累积**，即使输出已经顶到上限了，积分还在涨——等设定值降下来、需要减小输出时，积分已经涨得太大，于是回不来。

> **这里曾经有两个 bug，值得记住教训。**
>
> 一是 `nargin` 判断写错了一位（函数只有 10 个参数，却写成 `nargin < 11`），
> 导致调用方传进来的 `limits` 每次都被清空——**限幅从头到尾没生效过**。
>
> 二是当时的思路是「靠是否传 `limits` 来切换有/无抗饱和」，也就是「不传 limits 就是
> 无抗饱和版」。这个思路本身是错的：不传 limits 等于**完全不限幅**，根本不是
> 「无抗饱和」。两个错误叠在一起，面板 (c)(d) 就变成了两条都不限幅的曲线，
> 什么也演示不出来。
>
> 现在改成显式的 `antiwindup` 开关，语义清楚，且和 Python 里的 `NaivePositionPID`
> 一一对应。

### 5. 为什么增量式的限幅代码**没有**「条件积分」却依然抗饱和

```matlab
% sim_incremental 里的限幅
if ~isempty(limits)
    if u(k) > limits(2)
        u(k) = limits(2);
    elseif u(k) < limits(1)
        u(k) = limits(1);
    end
end
```

增量式没有单独的积分累加器，它唯一「记得」的过去信息是 `u_last`。而 `u_last` 在下一步里会被 `u(k) = u_last + du` 使用，`u(k)` 又被限幅夹住了。所以**输出被夹住 → 记忆也被夹住**，积分根本无处累积。这就是「天然抗积分饱和」——不需要写任何额外代码，结构上就避免了这个问题。

### 6. 为什么增量式要保存 `e_prev2`（两个历史误差）

```matlab
du = kp*(e - e_prev) + ki*e*dt + kd*(e - 2*e_prev + e_prev2)/dt;
```

微分项需要 `e[k] - 2*e[k-1] + e[k-2]`，用到了**前两拍**的误差，所以除了 `e_prev`（e[k-1]）还要存 `e_prev2`（e[k-2]）。这是增量式 PID 的「代价」：多存一个历史值。

移位更新：

```matlab
e_prev2 = e_prev;   % 旧的 e[k-1] 变成 e[k-2]
e_prev  = e;        % 当前 e 变成 e[k-1]
u_last  = u(k);     % 当前输出变成下一次的"上一次输出"
```

### 7. 为什么设定值序列写成矩阵 `[0.0, 3.0; 5.0, 0.5]`

```matlab
setpoint_seq = [0.0, 3.0; 5.0, 0.5];   % (时刻, 设定值)
```

这是一张「时间表」：第 1 行表示「从 t=0 开始设定值是 3」，第 2 行表示「从 t=5 开始设定值变成 0.5」。`current_setpoint` 遍历这张表，返回当前时刻生效的设定值。

为什么要先设 3 再降到 0.5？因为**要逼控制器饱和**：设定值 3 远超限幅上限 1，控制器会一直顶在上限，积分才有机会涨到爆炸——这正是演示「积分饱和」需要的条件。

## 四、看懂图：四个面板各看什么

- **(a)(b) 微分冲击 + 两者等价**：图 (b) 里 t=0 有一根很高的尖峰（纵轴到 33），那是设定值从 0 跳到 1 的瞬间 `Δe/dt` 爆炸的结果。**两条曲线在这根尖峰上完全重合**——因为配平后的增量式就是位置式的差分形式，代数上等价。所以这一组图的正确读法不是「谁更平滑」，而是「尖峰从哪来，以及它和实现方式无关」。
- **(c)(d) 积分饱和 —— 这才是真正的区别**：看 (c)，设定值在 5 秒降到 0.5 之后，无抗饱和的位置式（蓝）**卡在 1.0 再也下不来**，因为积分在饱和期间涨过头了，松手时「欠账」太大；增量式（橙）则稳稳落到 0.5。(d) 里位置式的 u 一直贴在 1.0 不动，正是「表面看没动、内里积分在偷偷涨」的证据。

> 所以增量式 PID 真正的卖点是：**天然抗积分饱和 + 无扰动切换**，而不是「更平滑」。
> 代价是输出是「增量」而非「绝对量」，工程里通常两者都实现，按执行器类型选。
> 至于微分冲击，两种形式都躲不掉，要消除它得改用**微分先行**。
